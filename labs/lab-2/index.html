Meeting Notes to a Controlled Excel Action Register

Compare meeting notes with an existing action register, approve a field-level delta and update only the authorised Excel cells.

Level 200 Duration 35–45 min Format Guided hands-on lab
Workshop path: Documents, communication and Excel controls

Lab details

LevelPersonaDurationPurpose
200Project manager, business analyst, PMO, action owner35–45 minutesConvert meeting evidence into controlled, auditable updates without overwriting unchanged Excel fields.

Download the participant files

Download all three files before starting. Keep the original workbook unchanged until the review queues are complete.

  • Project Atlas meeting notes (.docx) — the authoritative meeting evidence.
  • Project Atlas action register (.xlsx) — the working register, review queues, snapshot, audit and validation sheets.
  • Copilot prompt card (.pdf) — copyable prompt sequence and control rules.
Synthetic data

The case contains no customer, employee or production information. Use only the supplied files during the workshop.

The central control rule

One confirmed parameter means one changed field

For an existing Action ID, change only the field explicitly changed in the meeting. Preserve every other cell exactly as it appears in the current Excel row.

Meeting evidenceCorrect Excel effectIncorrect effect
“ACT-014 is due 11 September, not 10 September.”Change only Due Date.Regenerate the full ACT-014 row or alter owner, status, dependency, notes or source.
“Sofia takes ACT-016 from Mark. The deadline remains 11 September.”Change only Owner.Change the owner and rewrite the confirmed unchanged deadline.
Two people state different dates for ACT-021 and no agreement follows.Classify HOLD; preserve the existing date.Select the date that sounds more likely.

Learning objectives

After completing this lab, you will be able to:

  • ground Copilot in the supplied meeting notes and current Excel register;
  • match evidence to an Action ID before proposing an edit;
  • create one comparison row for each explicitly changed field;
  • distinguish updates, additions, confirmations, conflicts, duplicates and general discussion;
  • approve, reject or hold every proposed change before editing;
  • prove that unchanged fields remained identical.

Running scenario

Project Atlas is preparing to enter user acceptance testing. The 8 September readiness meeting changes several dates, changes one owner, completes one action, confirms one existing date, introduces two complete new actions and leaves two items unresolved or uncommitted.

The workbook begins with eight existing actions, ACT-014 through ACT-021. Your job is not to replace the register with a new interpretation. Your job is to produce a controlled delta against the current register.

Expected challenge

Several sentences sound like actions, but only evidence with the required confirmed values may become a new row. A confirmation that matches Excel is NO_CHANGE, not an update.

Prerequisites

  • A work or school account with access to Microsoft Copilot Chat.
  • Microsoft Excel for the web or desktop.
  • The three participant downloads above.
  • Permission to upload or reference the supplied workshop files.
  • Approximately 45 minutes and a working copy of the Excel file.
Capability check

This lab requires Copilot in Excel Edit mode for workbook changes. If Edit mode is missing in desktop Excel, open the workbook in Excel for the web and try again. Do not transfer Copilot results into the workbook manually.

Exercise 1: Inspect and ground both sources

  1. Open the meeting-notes document and read the chair’s control rule.
  2. Open the workbook and review Instructions, Action Register and Before Snapshot.
  3. In Microsoft Copilot Chat, turn on Work IQ if your licensed experience provides it.
  4. Reference or upload both supplied files.
  5. Run the source-check prompt. Stop if Copilot cannot name both files or locate the Action Register sheet.
Source check
Use only the referenced Project Atlas meeting notes and Action Register.

Before analysing them, name both sources and tell me which Excel sheet contains the current master actions.

Confirm the meeting date, the Action ID format and the current values in each matched row. If either source is unavailable, stop and tell me.

Exercise 2: Extract a field-level delta

Ask Copilot to compare the evidence with the existing register. An existing action can produce more than one proposal, but every proposal must name exactly one changed field.

Field-by-field comparison
Compare the meeting notes with the existing Action Register field by field.

First, match each relevant statement to an existing Action ID.

For an existing action:
- Read the complete current Excel row.
- Identify only fields explicitly changed during the meeting.
- Create one proposed-change row for each changed field.
- Include the current Excel value and the proposed meeting value.
- Preserve every field not explicitly changed.
- Do not regenerate or replace the complete action row.
- Do not replace current values with blank, “Not confirmed” or inferred values.
- If the new value equals the current value, classify it as NO_CHANGE.
- If information conflicts, classify it as HOLD.

For information that does not match an existing action:
- Determine whether it is a confirmed new action.
- Use ADD_ACTION only when the task, owner and required values are sufficiently clear.

Return: Change ID, Action ID, Classification, Field to change, Current value, Proposed value, Exact evidence, Missing or conflicting information, Human decision.

Use only these classifications:

ClassificationMeaningWorkbook effect
UPDATE_FIELDOne existing field has an explicit new value.One proposed cell change.
ADD_ACTIONA sufficiently complete new commitment.Candidate in New Action Queue.
NO_CHANGEMeeting confirms the value already in Excel.No edit.
DUPLICATEThe proposed item is already represented.No new row.
HOLDRequired information conflicts or is missing.Preserve current data; ask for clarification.
NOT_AN_ACTIONDiscussion, suggestion or idea without a commitment.No edit and no new row.

Exercise 3: Populate the review queues

  1. Open the supplied workbook in Excel and open Copilot.
  2. Select Edit mode. Reference the meeting-notes document.
  3. Run the direct-edit prompt below. Review the proposed target sheets and row count.
  4. Confirm the plan only when every existing-action candidate changes exactly one field.
  5. Apply the change, then verify the populated queues. Do not edit the Action Register yet.
Write candidates directly into Excel
You are editing Project_Atlas_Field_Level_Action_Register.xlsx in Excel Edit mode.

Using only the referenced Project_Atlas_UAT_Readiness_Meeting_Notes.docx and the current Action Register:
1. Write one row per UPDATE_FIELD candidate into Field Change Queue.
2. Write each ADD_ACTION candidate into New Action Queue.
3. Preserve the exact Action ID and current Excel value.
4. Fill exact evidence and any missing or conflicting information.
5. Leave Human Decision as Pending for human review.
6. Do not edit Action Register, formulas, validation, formatting or any other sheet.

Before editing, show the target sheets, target ranges and planned row count. Wait for my confirmation, then apply.
Exception review
Review the proposed queues before any workbook edit.

Flag:
1. A proposed change whose current value does not match Excel
2. A field change not supported by exact meeting evidence
3. A changed owner or deadline inferred rather than confirmed
4. A conflict that should remain HOLD
5. A suggestion converted into an action
6. A proposed full-row replacement for an existing action

Do not edit the workbook. Return only the exceptions and one clarification question for each.

Exercise 4: Apply the human approval gate

Set Human Decision independently for every queue row.

  • Approve only when the Action ID, exact field, current value, proposed value and evidence all agree.
  • Hold when required information conflicts or is missing.
  • Reject confirmations, suggestions, duplicates and unsupported changes.
Do not approve a complete replacement row

For an existing Action ID, approval belongs to the one proposed field change. It does not approve Copilot to normalise, clean or recreate unrelated cells.

Exercise 5: Update the Action Register

Use Copilot in Excel Edit mode. First display the exact plan and confirm it before any cell changes. If Edit mode is unavailable, open the file in Excel for the web; do not use a manual transfer fallback.

Plan, then edit
Use the approved Field Change Queue and New Action Queue to update the Action Register.

Rules:
- Apply only rows where Human Decision is Approved.
- For UPDATE_FIELD, change only the named field in the specified Action ID.
- Preserve every other cell in that row exactly as it is.
- For ADD_ACTION, create one complete new row and assign the next sequential Action ID.
- Do not apply HOLD, DUPLICATE, NO_CHANGE, NOT_AN_ACTION or Rejected rows.
- Do not rewrite existing rows from memory.
- Preserve formulas, formatting, validation and table structure.

Before editing, show Action ID, exact field, current value and new value. Wait for confirmation before applying the changes.
  1. Compare Copilot’s plan with the approved queues.
  2. Confirm that each existing-action proposal contains only one field.
  3. Apply the five approved field changes.
  4. Add the two approved new actions with the next sequential IDs.
  5. Set Applied? to Yes only after the corresponding change is visible in the Action Register.

Exercise 6: Audit every changed cell

Populate Before-After Audit. Every changed cell must map to an approved Change ID or approved new-action candidate.

Before-and-after audit
Audit the updated Action Register against the Before Snapshot and approved queues.

List every changed cell. For each changed cell show Action ID, field, previous value, current value and matching approved Change ID.

Flag:
- Any changed cell without an approved Change ID
- Any approved change that was not applied
- Any unchanged field that was accidentally modified
- Any complete existing row that was replaced
- Duplicate Action IDs or missing required values

Do not make further edits.
  1. Open Validation and review the formula-driven counts.
  2. Complete all five final human checks.
  3. If a check fails, undo the unapproved edit or restore the original cell from Before Snapshot.

Success criteria

Limitations and good practice

Risk or limitationControl
Copilot may summarise a whole row instead of returning a delta.Require one output row per changed field and compare the current value first.
Copilot may infer a missing deadline, owner or priority.Use HOLD and ask a clarification question; never replace the current value with an inference.
Excel Edit mode is not visible.Open the workbook in Excel for the web, reopen Copilot and select Edit. If the tenant does not provide Edit mode, pause the lab rather than copying results manually.
Meeting wording can sound like agreement without creating a commitment.Require explicit task, owner and required values for ADD_ACTION.
Shared workbooks may change during review.Re-check the current Excel value immediately before applying each approved field change.
A correct final register can still hide an unsafe process.Keep the queues, before snapshot and changed-cell audit as evidence.

Test your understanding

  1. Why is a confirmed date that already matches Excel classified as NO_CHANGE?
  2. Why must the go/no-go date remain unchanged when two dates are stated?
  3. Why does a new action need more information than an update to one existing field?
  4. What evidence proves that an unchanged owner, status or dependency was preserved?
  5. Why is a full-row rewrite unsafe even when the intended deadline is correct?
Lab complete

You have used a controlled change process: ground, compare, classify, approve, edit and audit. The final control is not only that the new value is correct, but that every unrelated value stayed unchanged.
