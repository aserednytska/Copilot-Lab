Teach Copilot Your Tone of Voice

Create an evidence-based tone profile, test it with fixed facts and update one rule without changing everything else.

Synthetic and redacted data

The central control rule

Change one parameter at a time

When testing a tone update, keep the source facts, audience, purpose, format, length and all other tone rules unchanged. Otherwise you cannot tell which change caused the different result.

Stable voiceAdaptive toneNever invent
Clear, practical, outcome-led, evidence-aware and collaborative.Warmth, detail and terminology may adapt to the audience and situation.Facts, decisions, owners, deadlines, risks or confidence that are not supported by the source.

Learning objectives

After completing this lab, you will be able to:

  • select suitable samples without exposing sensitive information;
  • ask Copilot to identify patterns rather than imitate exact sentences;
  • accept, edit or reject every proposed tone rule;
  • create a concise, reusable tone profile with explicit boundaries;
  • apply the profile in Copilot Chat or a Copilot Notebook;
  • score baseline, v1.0 and v1.1 against the same fixed case;
  • update exactly one rule and retain the prior approved version;
  • adapt tone by audience without changing the underlying facts.

Running scenario

You are an independent consultant and business analyst. You repeatedly prepare project updates, requirements, meeting follow-ups and decision material. Copilot can draft faster, but its default output often sounds generic, too formal or unlike you.

You will derive a controlled profile from approved samples, apply it to a Project Atlas client update and then process one piece of feedback: the message opening and closing should feel slightly warmer for an existing client.

What remains fixed

The Project Atlas facts, audience, purpose, length, directness, structure, owner and deadline remain unchanged. Only opening and closing warmth may change from v1.0 to v1.1.

Prerequisites

Exercise 1: Produce the baseline

  1. Open the Project Atlas Communication Case.
  2. Start a new Copilot Chat without referencing any writing samples or tone profile.
  3. Run the baseline prompt below.
  4. Open the Excel scorecard in Edit mode and ask Copilot to write the baseline draft and scores directly into Output Scores. Review the target row before applying.
Baseline draft
Using only the Project Atlas case facts, draft a client update of 140–180 words.

Audience: existing client project sponsor.
Purpose: explain the current UAT position, the open restriction and the next action.

Do not invent facts, owners, dates or decisions.

Exercise 2: Find candidate patterns

  1. Open the Hanna Tone-of-Voice Sample Pack.
  2. Attach or reference only that file in a new Copilot Chat.
  3. Run the pattern-analysis prompt.
  4. Open the Excel scorecard in Edit mode and run the direct-edit prompt below.
Evidence-based pattern analysis
Analyse only the attached approved writing samples.

Identify recurring patterns in:
- message opening and ordering;
- level of context;
- sentence length and directness;
- use of bullets and headings;
- treatment of facts, recommendations and uncertainty;
- technical language;
- calls to action and closings.

For every proposed rule, cite at least two sample IDs when possible.
Label the evidence Consistent or Uncertain.
Separate stable voice patterns from audience-dependent tone choices.
Do not copy distinctive phrases or infer personality traits that the samples do not prove.
Write candidates directly into Rule Review
You are editing Lab_4_Tone_Evaluation_and_Version_Scorecard.xlsx in Excel Edit mode.

Analyse only the referenced Lab_4_Hanna_Tone_of_Voice_Sample_Pack.docx.
Write each proposed rule as one new row in Rule Review.
Populate Rule ID, proposed rule, sample evidence, stable or audience-dependent, confidence and rationale.
Leave Human Decision blank or Pending for human review.
Do not edit any other sheet, formula, validation or formatting.

Show the target range and planned row count. Wait for confirmation, then apply.

Exercise 3: Apply human validation

Copilot proposes patterns; you decide whether each is a real rule. In the Rule Review sheet, choose Accept, Edit, Reject or Insufficient evidence.

DecisionUse when
AcceptThe pattern is supported across samples and should guide future drafts.
EditThe pattern is useful but too absolute, vague or audience-specific.
RejectThe proposal is case-specific, contradictory or unlike your intended voice.
Insufficient evidenceThe available samples do not support a confident rule.
Common false rule

“Always use bullets” is too absolute. Use bullets when they improve scanning or separate several actions; a one-sentence update may not need them.

Exercise 4: Build tone profile v1.0

Open the Tone Profile and Change-Control Template in Word and use Edit with Copilot to build the profile directly from the accepted or edited rows in the Excel Rule Review sheet.

Create the controlled profile
Using only the human-approved rules below, create Tone Profile v1.0.

Structure it as:
1. Stable voice
2. Default writing rules
3. Audience adaptations
4. Words or patterns to avoid
5. Factual and governance boundaries
6. Final self-check

Keep the complete instruction under 1,500 characters where possible.
Do not add a rule that was not approved.
Do not tell Copilot to copy sample phrases exactly.

Use only rows in the referenced Excel Rule Review sheet where Human Decision is Accept or Edit.
Preview the changes and wait for confirmation before keeping them.

After confirming the Word preview, open the scorecard in Excel Edit mode and ask Copilot to record the complete approved instruction or controlled document reference in Tone Versions as v1.0.

Exercise 5: Apply v1.0 in Copilot

Option A: Use the profile in a prompt

  1. Open a new Copilot Chat and attach the Project Atlas case.
  2. Paste the complete v1.0 profile above the drafting request.
  3. Generate the same 140–180 word client update.
  4. Score it in the Excel workbook without changing the case or audience.

Option B: Save custom instructions

  1. In Microsoft 365 Copilot, select Settings and more (…).
  2. Open Chat settings, then Personalization.
  3. Open Custom instructions and select Edit instructions.
  4. Paste the approved v1.0 instruction and select Save.
  5. Start a new chat and run the fixed Project Atlas task.

Option C: Use a Copilot Notebook

  1. Create or open a Copilot Notebook for the tone experiment.
  2. Add the sample pack, Project Atlas case and approved Tone Profile document as references.
  3. Select More options (…) in the Notebook.
  4. Select Instructions.
  5. Paste the approved v1.0 profile and select Save.
  6. Ask the Notebook to draft the fixed Project Atlas client update.
Do not combine paths during the test

Use one active source of tone instruction for each comparison. Duplicate or conflicting instructions make the result difficult to interpret.

Exercise 6: Score v1.0 against the baseline

Open the scorecard in Excel Edit mode and ask Copilot to write both drafts, the 1-to-5 criterion scores and unsupported-addition count directly into Output Scores. Review the two target rows before applying.

  • Approve only if factual fidelity remains strong and unsupported additions equal zero.
  • A more pleasant draft is not automatically better.
  • If v1.0 changes facts or weakens clarity, revise the profile before continuing.

Exercise 7: Define one requested update

The stakeholder feedback is:

“The content is clear, but the opening and closing still feel slightly formal for an existing client.”

Complete change request TCR-001 in the Excel workbook. The proposed change is limited to opening and closing warmth.

ChangeMust remain unchanged
For existing clients, use a short natural update at the opening and a brief collaborative invitation at the close when appropriate.Facts, audience, purpose, length, directness, structure, owner, deadline and all other profile rules.

Exercise 8: Run the one-parameter test

Controlled rewrite
Rewrite the v1.0 Project Atlas client update using one approved change only:

For an existing client, make the opening slightly more natural and the closing slightly more collaborative.

Keep unchanged:
- every fact, owner, date and restriction;
- the existing-client audience;
- purpose and 140–180 word length;
- directness, clarity, structure and all other v1.0 rules.

Return:
1. Revised draft
2. Exact sentences changed
3. Confirmation that no other parameter changed
4. Any unintended difference you detected

Ask Copilot in Excel Edit mode to write the exact before-and-after sentences directly into Before After and identify every changed parameter. If another parameter changed, reject the result and rerun the test.

Exercise 9: Approve and install v1.1

  1. Ask Copilot in Excel Edit mode to add the revised output and scores to Output Scores.
  2. Confirm warmth improved and the other dimensions remained stable or improved.
  3. Confirm unsupported additions equal zero.
  4. Approve TCR-001 or mark it Revise, Reject or Roll back.
  5. If approved, ask Edit with Copilot in Word to create v1.1 by changing only the relevant rule in the complete profile.
  6. Save the complete result as v1.1. Do not overwrite v1.0.
  7. Update the active prompt, Custom Instructions or Notebook Instructions with the complete approved v1.1 text.
Replace the complete instruction

Do not paste only “be warmer” as an extra instruction. Replace the complete active profile with approved v1.1 so the governing rules remain clear and non-contradictory.

Exercise 10: Test audience adaptation

Using v1.1 and the same facts, create three versions: existing client, technical lead and executive sponsor. Then compare them.

Audience comparison
Using the approved Tone Profile v1.1 and only the Project Atlas case facts, create three short updates for:
1. Existing client project sponsor
2. Technical lead
3. Executive sponsor

Keep the facts and decision status identical.
Adapt only the level of detail, terminology and emphasis required by each audience.

After the drafts, list:
- what remained part of the stable voice;
- what changed as audience-dependent tone;
- any fact that could not be preserved consistently.
Teaching point

Your voice can remain stable while tone adapts. A technical audience may need more detail; an executive may need the decision and impact first.

Success criteria

Limitations and good practice

Risk or limitationControl
Too few or too-similar samples create a false rule.Use several approved examples from different communication tasks.
Copilot may overfit to distinctive phrases.Ask for patterns, not imitation, and reject copied wording.
A tone profile can conflict with the current task.State audience, purpose and format in the task prompt; keep the profile concise.
Custom instructions may affect unrelated chats.Use a Notebook or paste the profile per task when the context should stay isolated.
Several simultaneous changes make comparison invalid.Change one parameter and keep the fixed case unchanged.
A warmer version may become longer or less direct.Score every output on multiple dimensions, not warmth alone.
AI can still invent or distort facts.Compare the final draft with the source and reject unsupported additions.
Sample content can contain sensitive information.Use approved, redacted examples and follow organisational data rules.

Test your understanding

  1. Why should Copilot propose rules but a human approve them?
  2. What makes a tone rule too absolute?
  3. Why must the Project Atlas facts and audience remain fixed during the v1.0–v1.1 comparison?
  4. What evidence would make you reject a warmer output?
  5. When is a Notebook better than account-wide custom instructions?
  6. How would you roll back after an unsuccessful tone update?
