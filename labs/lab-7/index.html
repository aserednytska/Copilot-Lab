Case: Project Aurora

The IT PMO maintains a SharePoint project register. Management wants one live dashboard showing portfolio health, financial and schedule exceptions, decision requirements and data freshness.

The challenge is not only to create a polished report. Participants must prove that it is connected to the correct source and does not hide the problems inside that source.

Source problemExampleRequired dashboard treatment
Missing ownershipIT-009 and IT-012Display Not confirmed; do not infer the owner.
Conflicting statusIT-015 is Green and 45 days lateShow both fields; do not overwrite RAG.
Invalid financial valueIT-018 forecast cost is negativeKeep a visible warning and qualify portfolio totals.
Incorrect calculationIT-003 and IT-029 variance fieldsShow the mismatch; do not silently repair it.
Stale informationIT-021 and IT-030Include a freshness warning.
Missing categoryIT-030 RAG is blankCount it as Not confirmed rather than excluding it.

Learning objectives

  • create a SharePoint list from a structured Excel table;
  • inspect source quality before visualisation;
  • propose and approve a dashboard contract;
  • generate an interactive HTML report connected to a SharePoint List;
  • refine the report without editing its source;
  • reconcile dashboard totals with formula-driven controls;
  • change one source field and verify the exact expected impact;
  • reject or qualify an attractive but unsafe management conclusion.

Prerequisites

  • Permission to create a Microsoft List on an approved SharePoint site.
  • An active Microsoft Copilot licence.
  • Copilot in SharePoint available for the tenant and site.
  • The participant downloads above.
Preview availability

Copilot in SharePoint is currently a preview capability. Microsoft says it rolls out to licensed users and can be controlled by administrators for the tenant or selected sites. If it is missing, use the trainer demonstration path instead of rebuilding the report manually.

Exercise 1: Create the SharePoint source list

  1. Open the target SharePoint site.
  2. Select New > List.
  3. Select From Excel.
  4. Upload Lab_7_Project_Aurora_SharePoint_Import_Data.xlsx.
  5. Select ProjectRegisterTable.
  6. Name the list IT Project Delivery Register.
  7. Review the detected column types.
  8. Select Create.
  9. Confirm that the list contains Project IDs IT-001 to IT-030.
Keep the test data unchanged

Do not clean, correct or complete the deliberate source problems before creating the dashboard.

Exercise 2: Inspect before creating

  1. Open Copilot from the SharePoint experience.
  2. Run the inspection prompt.
  3. Compare Copilot's findings with Data Quality Review in the validation workbook.
  4. Reject any proposed automatic correction.
Inspect the list
Review the SharePoint list IT Project Delivery Register.

Before creating anything, report:
1. the fields and likely data types;
2. fields containing blank values;
3. records containing logically conflicting information;
4. values that may create misleading dashboard results;
5. fields that should be treated as categories, dates, currency or numbers.

Do not modify the list.
Do not correct or infer missing information.
Reference the Project ID for every issue.

Exercise 3: Propose the dashboard contract

Ask Copilot to describe the report before it creates anything. The human approves the structure, calculations and missing-data rules.

Propose before creating
Using only the SharePoint list IT Project Delivery Register, propose an interactive project portfolio dashboard.

Include:
- KPI cards for active projects, Red projects, projects over budget, projects forecast late, stale updates and decisions required;
- filters for Department, Project Manager, Stage, RAG Status and Decision Required;
- charts for RAG distribution, projects by stage, approved budget versus forecast cost and schedule variance;
- a searchable exception table;
- links to the related SharePoint list items.

Rules:
- do not invent or correct missing values;
- display missing values as Not confirmed;
- do not infer RAG from dates or budget;
- keep conflicts visible;
- show the source-list name and data date;
- show the proposed structure and wait for confirmation.

Exercise 4: Create the connected interactive report

  1. Review the proposed components and KPI definitions.
  2. Confirm that a visible data-quality warning is included.
  3. Approve the plan.
  4. Ask Copilot to create the interactive HTML report.
  5. Open the result and test its filters, search, sorting and source links.
Create the report
Create the approved interactive HTML dashboard from IT Project Delivery Register.

Keep the report connected to the underlying SharePoint list.
Do not modify list items.
Include the approved KPIs, filters, charts, searchable exception table, source links and visible data-quality warning.

Use Not confirmed for missing values.
Do not resolve source conflicts.
What connected means

The report is based on the SharePoint List instead of a copied static snapshot. Refresh or reopen it after a controlled list change to verify that the report uses current source data.

Exercise 5: Refine the report without changing the source

Dashboard-only refinement
Update only the dashboard presentation.

Add:
- a combined Red and Amber exception filter;
- a warning for records not updated within 14 days;
- sorting by Open Critical Issues, then Schedule Variance Days;
- a Decision Required section;
- a data-quality count for records with missing or conflicting information.

Keep the SharePoint list and every source field unchanged.
Show the proposed dashboard changes and wait for confirmation.

After Copilot applies the approved refinement, reopen IT-003, IT-018 and IT-029 from the exception table. Confirm that their financial warnings remain visible.

Exercise 7: Run the one-field controlled test

Authorised source change: IT-017 RAG Status changes from Amber to Red. No other field may change.

Step 1: Predict the impact

Impact check before editing
Controlled test: change only IT-017 RAG Status from Amber to Red.

Before any change, identify exactly which dashboard KPI, chart and table row should change.
Return before value, expected after value and expected delta.

List every KPI and source field that must remain unchanged.
Do not modify anything yet.

Step 2: Apply only the approved source-field change

One-field direct-edit prompt
Update only the RAG Status field of SharePoint list item IT-017 from Amber to Red.

Do not edit another field, item, list setting or dashboard definition.
Show the exact target item and field, wait for confirmation, then apply.
Return the before-and-after value and confirm the item ID.
If direct list editing is unavailable

Open IT-017 in the SharePoint List and change that single field. This is a controlled source update, not a manual transfer of Copilot output.

Exercise 8: Challenge the management story

Safe management conclusions
Analyse the dashboard and provide three management conclusions.

For every conclusion:
- identify the supporting SharePoint records;
- separate a confirmed fact from an interpretation;
- identify missing or contradictory data;
- state whether management can safely act on it;
- name the human role that owns the final decision.

Do not treat a visually prominent chart as proof that the source data is correct.
Required human correction

Reject or qualify any conclusion that the portfolio is under budget. The aggregate includes an invalid negative forecast cost and two incorrect reported variances.

Success criteria

Limitations and troubleshooting

ProblemControl
Copilot in SharePoint is missing.The preview may not have reached the tenant or site, or an administrator may have excluded it. Use the trainer demonstration path.
Interactive report creation is unavailable.Do not manually build substitute HTML. Observe the demonstration and complete the source and validation exercises.
Wrong totals appear.Check field types, filters, blank handling and invalid values before changing anything.
The dashboard appears static.Reopen or refresh it and confirm that it was created from the list rather than a copied snapshot.
List-item links do not open.Confirm the links and the viewer's SharePoint permissions.
A large list performs poorly.Use indexed columns and filtered views. SharePoint list-view thresholds can affect queries.
Advanced modelling is required.Use Power BI for governed semantic models, advanced calculations and enterprise BI lifecycle needs.
