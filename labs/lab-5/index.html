Central rule

Save the reusable structure, not the client-specific content. A successfully saved prompt is convenient; it is not automatically tested, approved or safe.

Learning objectives

  • identify recurring consulting and business-analysis work;
  • convert a one-off prompt into Goal, Source, Context and Expectations;
  • replace client facts with clear placeholders;
  • test the same prompt on two different cases;
  • detect hidden assumptions and chat-context leakage;
  • approve, version, update, retire and roll back prompts;
  • find the hidden Save prompt bookmark and verify the saved item in Prompt Lab.

Weak one-off prompt

Exercise 3: Build the reusable GSCE version

PartQuestion
GoalWhat should Copilot produce?
SourceWhich exact content is authoritative?
ContextWho uses the output and for which decision?
ExpectationsWhich structure, limits, evidence and uncertainty rules apply?
BA-03 reusable prompt
Goal
Review [SOURCE] and prepare a requirements-evidence register for [PROJECT].

Context
The register will be reviewed by [AUDIENCE] to support [PURPOSE OR DECISION].

Source
Use only [APPROVED SOURCE]. Do not use another project or general knowledge.

Expectations
For every item include:
- Requirement ID
- Requirement statement
- Requirement type
- Source evidence
- Stakeholder
- Acceptance condition
- Confidence
- Open question

Separate confirmed requirements, assumptions and recommendations.
Do not invent an owner, deadline or decision.
Write "Not confirmed" when evidence is missing.

Exercise 4: Test Project Meridian

  1. Start a new Copilot Chat.
  2. Reference only the Meridian case pack.
  3. Complete every placeholder.
  4. Run BA-03.
  5. Score the result in the Excel Test Log.
  6. Record unsupported additions and hidden assumptions.

Exercise 5: Test Project Harbor unchanged

  1. Start another new chat to avoid Meridian context leakage.
  2. Reference only the Harbor case.
  3. Reuse the same prompt structure.
  4. Replace only project, source, audience and purpose placeholders.
  5. Run and score it.
Failure signal

If the Harbor output mentions suppliers, SAP, compliance screening or another Meridian detail, the prompt is overfitted or the conversation context is contaminated.

Exercise 6: Approve v1.0

Approve only when both cases pass, unsupported additions equal zero, missing information stays visible, output structure remains stable and no client-specific content remains in the template.

Exercise 8: Find the Save prompt bookmark

Where exactly is it?

The bookmark is attached to the prompt message that you sent. It is not attached to the Copilot answer. The icon may remain hidden until you hover over your sent prompt.

Detailed desktop steps

  1. Open Microsoft 365 Copilot Chat in the desktop browser or desktop application.
  2. Paste and send the complete reusable prompt.
  3. Wait until Copilot has successfully finished its response.
  4. Move your mouse pointer back up to your sent prompt message.
  5. Hover over the prompt. Do not hover over the Copilot answer.
  6. A small action row should appear beside or immediately beneath your prompt message.
  7. Look for an outline bookmark icon. When you place the pointer on it, the tooltip should say Save prompt.
  8. Select the bookmark.
  9. If Copilot asks for a title, use the controlled name: BA-03 - Requirements Evidence Register.
  10. Confirm the save action.

Confirm that the prompt was saved

  1. Return to the message box at the bottom of Copilot Chat.
  2. Select Prompt Lab below the message box. Depending on the interface, you may first need to select a prompt pill or More (...).
  3. Open Your prompts or Your saved prompts.
  4. Find BA-03 - Requirements Evidence Register.
  5. Open it and confirm that `[PROJECT]`, `[SOURCE]`, `[AUDIENCE]` and the other placeholders are still present.
  6. Confirm that no Meridian or Harbor facts were saved.

If the bookmark does not appear

  1. Confirm the prompt was sent and the response completed successfully.
  2. Hover over your prompt message slowly; the controls can remain hidden otherwise.
  3. Widen the Copilot window because compact layouts may collapse actions.
  4. Look for More actions (...) on the prompt message and check whether Save prompt is inside it.
  5. Try Microsoft 365 Copilot on the web if you are using another application.
  6. Open Prompt Lab directly and check whether you can create or manage prompts there.
  7. If saving is unavailable, keep Excel as the controlled library and reference the workbook from Copilot; do not maintain a second manually copied prompt.
Current Microsoft behaviour

Microsoft documents the save path as: run the prompt successfully, hover over the prompt to reveal the bookmark, select Save prompt, and access it later from Prompt Lab under your saved prompts.

Exercise 9: Share carefully

Before sharing a prompt link or team prompt, remove client names, actual dates, confidential source links, fixed commitments and sensitive examples. A shared link does not make the prompt organisationally approved.

Exercise 10: Maintain and update the library

  1. Create a Prompt Change Request.
  2. Name the one rule or field being changed.
  3. Record what must remain unchanged.
  4. Create the proposed new version.
  5. Retest Meridian and Harbor.
  6. Approve, revise, reject or roll back.
  7. Retain the previous approved version.
  8. Retire duplicated or unsafe prompts with a reason and replacement.

Success criteria

Limitations and good practice

RiskControl
A saved prompt still produces variable output.Keep source and output controls explicit; verify each result.
One-case testing hides assumptions.Require two meaningfully different cases.
Chat context leaks between projects.Use a new chat and exclusive source boundary for each test.
Client content remains inside the saved prompt.Replace it with placeholders before saving.
A newer version performs worse.Retest both cases and retain rollback.
Prompt Lab or bookmark is unavailable.Use the Excel library as the source of truth and reference the approved prompt row/file from Copilot.
Team sharing is mistaken for approval.Use status, owner and version fields in the controlled library.
