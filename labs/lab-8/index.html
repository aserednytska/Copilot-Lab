Case: one agent, three project-delivery outcomes

The PMO has an approved project register, later weekly updates, contradictory meeting evidence and an Excel change-control table. Repeating long prompts every week is slow and inconsistent, so the team wants a grounded agent with stable rules.

Use caseAgent outcomeHuman responsibility
Weekly portfolio healthFacts, exceptions, decisions and unknowns with citationsConfirm the management interpretation
Controlled field-level changesOne row per explicit delta; all other fields preservedApprove the change and verify write-back
Steering committee briefEvidence-grounded status, conflicts and decision requestsOwn decisions, message and distribution

Learning objectives

  • distinguish a reusable agent from a one-off chat prompt;
  • configure a declarative agent in Microsoft 365 Copilot;
  • use a visible source hierarchy to manage conflicting evidence;
  • design exact instructions for authority, citations and missing information;
  • test normal, missing, conflicting, manipulative and permission-boundary cases;
  • change one instruction at a time and retest;
  • use Copilot in Excel to write approved changes directly without manual copying;
  • share only after critical release controls pass.

Prerequisites and capability check

  1. Sign in to the Microsoft 365 Copilot app with an organisational account.
  2. Open the left navigation and confirm that Agents is visible.
  3. Select Agents and confirm that New Agent is available.
  4. Confirm that the participant can access the approved SharePoint workshop folder.
  5. Confirm that Copilot is available in Excel for the direct-update exercise.
Availability varies

Agent Builder, supported knowledge sources, connectors and sharing depend on licence, rollout and administrator policy. If New Agent is unavailable, use the supplied blueprint and evaluation workbook as a design-and-test path.

The control model

PrioritySourceRule
1Approved Project RegisterAuthoritative current record
2Signed decision log and PMO policyAuthoritative decision and governance evidence
3Formal weekly updateMay support a proposed one-field delta
4Meeting notesContext; decisions require confirmation
5Chats and draftsWorking evidence only; never silently override higher sources
Agent versus automation

This agent interprets evidence and proposes controlled changes. It does not automatically become a trusted system writer. The supported target application or an approved workflow performs write-back, and a human verifies the result.

Exercise 1: Create the Project Delivery Control agent

  1. Open the Microsoft 365 Copilot app.
  2. Select Agents in the left navigation.
  3. Select New Agent.
  4. Select Skip to configure for the controlled workshop route.
  5. In Name, enter Project Delivery Control.
  6. In Description, enter the description below.
  7. Paste the exact instruction block into Instructions.
Description
Grounded PMO assistant for weekly health checks, controlled field-level change proposals and steering briefings.
Project Delivery Control instructions
You are the Project Delivery Control agent for a controlled PMO workshop.

SOURCE PRIORITY
1. Approved Project Register
2. Signed decision log and PMO governance policy
3. Formal weekly update
4. Meeting notes
5. Chats and drafts

RESPONSIBILITIES
- Prepare weekly project and portfolio health checks.
- Compare later evidence with the current register and propose field-level changes.
- Prepare steering committee briefings.
- Cite the source for every material fact, proposed change, decision and exception.

OUTPUT CONTROL
- Separate every answer into: Facts; Proposed changes; Decisions required; Not confirmed.
- For a proposed existing-record change, return: Project ID, Field Name, Current Value, Proposed Value, Evidence ID, Evidence Quote and Validation Status.
- Change only the explicitly supported field. Preserve every other field.
- Treat a suggestion, estimate or planned discussion as unconfirmed.

SAFETY AND AUTHORITY
- Never invent a RAG status, owner, deadline, cost, decision or evidence.
- Never resolve conflicting sources yourself. Show the conflict and ask the authorised owner.
- Never approve or reject a business decision.
- Never claim a file or system was updated unless the action completed and evidence is available.
- Never silently edit the Project Register. For approved write-back, instruct the user to open the workbook in Excel and use Copilot in Excel to write directly to the Controlled Changes table. Do not ask the user to copy chat output manually.
- Respect the signed-in user's permissions. If evidence is unavailable, say what cannot be accessed.

STYLE
Use concise business language, short tables and explicit labels. Use “Not confirmed” for missing information.

  3. Confirm the agent can access Lab_8_Project_Aurora_Control_Register.xlsx.

  5. Do not add the trainer answer key.
  6. Do not add the incident workbook to this main agent; it belongs to the optional IT agent.
Source discipline

Agent Builder can support multiple knowledge sources, but an agent is easier to govern when each source has a clear purpose and authority. More files can increase ambiguity.

Exercise 3: Add starter prompts

Weekly health
Prepare the weekly portfolio health check. Separate Facts, Proposed changes, Decisions required and Not confirmed. Cite every material claim.
Field-level comparison
Compare the latest weekly updates with the current Project Register. Return only explicitly confirmed field-level deltas. Preserve every other field.
Steering committee briefing
Prepare a steering committee briefing with evidence, decisions required, unresolved conflicts and data-quality warnings.

Exercise 5: Write approved changes directly in Excel

  1. Complete the agent comparison and confirm the four approved deltas.
  2. Open Lab_8_Project_Aurora_Control_Register.xlsx in Excel for the web.
  3. Open Copilot inside Excel.
  4. Ask Excel Copilot to derive the confirmed deltas from Project Register and Weekly Update Evidence.
  5. Ask it to write the four rows directly to ControlledChangesTable.
  6. Review the proposed workbook edits and select Apply when available.
  7. Verify that Project Register remains unchanged.
  8. Ask Copilot to report the exact rows and cells changed.
Direct write-back prompt for Copilot in Excel
In this workbook, add the approved field-level changes to the Controlled Changes table.

Use Project ID and Field Name as the key.
Preserve the current value exactly.
Add only the approved proposed value and include the evidence reference.
Do not modify Project Register.
Do not add suggestions or unconfirmed estimates.
Stop and ask me if any required value is missing.

After writing, report the rows added and the cells changed.
If write-back is unavailable

Do not manually copy the rows. Demonstrate the correct prompt, record that the tenant or application capability is unavailable, and continue with the evaluation. A production automation route requires an approved supported action or workflow.

Exercise 6: Create, share and release safely

  1. When all critical tests pass, select Create.
  2. Run one final smoke test in the created agent.
  3. If sharing is permitted, select Share.
  4. For SharePoint-grounded knowledge, prefer Specific users.
  5. Confirm every recipient already has access to the knowledge files.
  6. Record the agent version and release decision in the evaluation workbook.
Sharing does not grant source access

The agent owner retains edit control. Recipients can use the shared agent, but they still need permission to the underlying knowledge.

Optional agent pattern A: Change Impact Reviewer

CR-042 proposes reducing UAT from 10 business days to 5 and moving launch two weeks earlier. The change request says there is no material impact, but the approved test strategy, security plan and vendor schedule disagree.

Change Impact Reviewer instructions
You are the Change Impact Reviewer.

Analyse proposed changes against the approved requirements baseline, architecture constraints, test strategy, delivery plan and change request.
Cite every material claim.
Separate Confirmed impacts, Possible impacts, Missing evidence, Questions for owners and Decision required.
Never approve or reject a change.
Never state that “no impact” is proven when supporting evidence is missing.
Preserve contradictions and show which authorised owner must resolve them.

Optional agent pattern B: IT Knowledge & Incident

Use an administrator-configured Copilot connector when available, or the supplied synthetic incident export as the reliable workshop fallback.

IT Knowledge & Incident instructions
You are the IT Knowledge & Incident agent.

Use only approved IT policies, current approved knowledge articles and accessible incident evidence.
Cite the article ID or incident signature for every material claim.
Distinguish approved procedure, observed practice, recurring pattern and knowledge gap.
If no approved procedure exists, say “No approved answer found” and propose a knowledge-backlog item.
Never expose personal data, invent a resolution or present an outdated article as current.

Limitations and troubleshooting

IssueControl
Agents or New Agent is missing.Check licence, rollout and tenant policy. Use the blueprint fallback.
SharePoint knowledge does not ground.Check the active Microsoft 365 Copilot licence, permissions and supported source.
Agent claims a workbook edit happened.Require action evidence. Do not accept a claim without a visible completed edit.
Copilot in Excel will not apply changes.Confirm Excel for the web, Copilot availability and that the target is a table. Do not switch to manual copying.
ServiceNow connector is missing.Use the supplied synthetic incident export.
Connector metadata filtering is inaccurate.Validate results against source records; custom fields such as Assigned To can be unreliable.
Power Automate action is unreliable.Do not promise live action. Microsoft lists Power Automate action limitations for declarative agents.
Answers differ between runs.Score citations, grounding and safety rather than identical wording.
