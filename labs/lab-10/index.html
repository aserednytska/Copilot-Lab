Case: Project Nova Phase 2

Project Nova is exploring a more consistent way to process access requests across five enterprise applications. The steering committee must now choose the next phase.

Application groupTechnical positionObserved request volumeDecision implication
ServiceNow, HR Core and GitHub EnterpriseApproved integration paths and test environments46 of 120 requests — 38.3%A controlled subset pilot is technically feasible.
FinanceHub and Power BI WorkspaceAPI/security and tenant-consent/design constraints remain open74 of 120 requests — 61.7%Most observed volume remains outside the ready scope.
Both agents may be correct

Researcher may conclude that a three-app pilot is technically feasible. Analyst may conclude that the same pilot covers only 38.3% of workload. These statements answer different questions. A human decides whether limited coverage is acceptable.

Learning objectives

  • choose the right agent for research, analysis, document creation and action;
  • use current Project Nova sources without letting external context override internal constraints;
  • profile data quality before calculating KPIs;
  • reconcile different but valid agent conclusions;
  • apply Trace, Rank, Uncertainty, Sign-off and Transfer to every handoff;
  • create or update files directly when the supported agent can do so;
  • stop Cowork at the approval boundary;
  • keep the final decision with authorised humans.

Where to check

  1. Open Microsoft Copilot with your organisational account.
  2. In the left navigation, look under Agents. If necessary, open All Agents or Agent Store.
  3. Look for Researcher, Analyst, Word, Excel, PowerPoint or Cowork. Frontier capabilities may be marked (Frontier).
  4. Record visibility, ability to open, and ability to attach the required source in the Capability Check sheet.
  5. Choose Path A, B or C. Do not spend lab time trying to bypass a tenant restriction.
Office-agent requirement

Microsoft currently documents Word, Excel and PowerPoint agents in the Tools menu and All Agents area when the tenant has enabled the required AI model. If they are absent, use the in-app Copilot fallback.

TRUST controls every handoff

GateQuestion before transferRelease evidence
T — TraceCan every material claim be linked to a precise source or calculation?Source, section/sheet, date and claim map.
R — RankAre approved, operational, draft, external and unverified sources distinguished?Authority hierarchy and conflict rule.
U — UncertaintyAre assumptions, missing values, contradictions and definition problems explicit?Confirmed, Calculated, Proposed and Not confirmed labels.
S — Sign-offWhich authorised human has approved this interpretation for reuse?Reviewer, decision owner, date and approval status.
T — TransferWhat exactly may the next agent reuse or act on?Approved payload, prohibited decisions and stop conditions.
No uncontrolled chaining

Do not paste an unreviewed Researcher report directly into Word Agent, or an unreviewed Analyst chart directly into PowerPoint Agent. Complete and release the TRUST handoff first.

Exercise 1: Prepare the evidence

  1. Download all participant source files.
  2. Save them to an approved OneDrive or SharePoint workshop folder.
  3. Open the Decision Brief and identify the authoritative decision question, constraints, status vocabulary and human decision owners.
  4. Open the Options Source Pack and note the three application-ready claim and the two unresolved integration constraints.
  5. Open the dataset and KPI Rules. Do not calculate KPIs until the quality issues have been profiled.
  6. Record the selected availability path in the Agent Comparison and Evaluation workbook.

Exercise 2: Investigate with Researcher

  1. In Microsoft Copilot, open Researcher under Agents.
  2. Attach or reference the Decision Brief and Three Rollout Options Source Pack.
  3. Paste the prompt below.
  4. Answer any clarification questions without adding unsupported facts.
  5. When the report is complete, inspect every material citation and record any external evidence separately from the internal source pack.
Researcher — compare the rollout options
Investigate the three Project Nova Phase 2 rollout options using the supplied Decision Brief and Three Rollout Options Source Pack as the authoritative internal sources.

You may add current external context, but label it separately and do not override named internal constraints.

For every material claim:
- cite the precise source;
- distinguish Confirmed, Calculated, Proposed and Not confirmed;
- rank internal approved evidence above draft or external context;
- preserve conflicts and missing information;
- state the human decision required.

Do not select or approve the final option.
Challenge the apparent conclusion
Challenge the claim that a technically feasible three-application pilot is sufficient.

Show:
1. which evidence supports technical feasibility;
2. which evidence limits business coverage;
3. what cannot be concluded from the sources;
4. which question requires a human decision.
Path C fallback

Use standard Copilot Chat, attach only the two approved Word sources, switch off web grounding when available, and require the same output structure.

Exercise 3: Analyse with Analyst

  1. Open Analyst under Agents.
  2. Select the + icon and Attach content.
  3. Attach the Access Request Dataset and KPI Rules.
  4. Paste the profiling prompt.
  5. Verify that Analyst finds the duplicate ID, negative duration, missing completion, classification mismatch, mixed completion definition and missing cost.
  6. Ask Analyst to create editable tables and charts, or use Copilot in Excel to write them directly into the workbook.
Analyst — profile before calculating
Profile this workbook before calculating any KPI.

Identify:
- duplicate IDs;
- negative or invalid values;
- missing values;
- classification conflicts;
- inconsistent completion definitions.

Then calculate request volume by application and the share covered by applications marked Integration Ready = Yes.

For every result, show the denominator, exclusions, formula or rule, evidence status and limitation. Treat the one-business-day threshold as Proposed, not Approved. Create editable tables and charts in the workbook.
Expected control figure

The ready-app calculation is 46 ÷ 120 = 38.3%. FinanceHub and Power BI account for 74 ÷ 120 = 61.7%. Request volume does not prove the same share of business value or risk.

Exercise 4: Reconcile the agents

Researcher resultAnalyst resultCorrect reconciliation
Three integrations are technically ready.They cover only 38.3% of observed requests.A subset pilot is feasible, but its representativeness and value remain a human judgement.
A controlled pilot can produce learning.Two completion definitions and data defects limit formal KPI claims.Start only with approved measures, exclusions and exit criteria.
Create the reconciliation
Compare the Researcher report with the Analyst findings.

Create four sections:
1. findings that agree;
2. findings that answer different questions but can both be true;
3. genuine conflicts or missing evidence;
4. decisions and conditions that require a human owner.

Do not choose the rollout option. Preserve the 38.3% denominator and every Proposed or Not confirmed label.

Exercise 5: Release a TRUST handoff

  1. Open the TRUST Agent Handoff Template.
  2. Trace each material claim to the source pack, dataset or verified calculation.
  3. Rank the internal approved sources above external context.
  4. Record the mixed completion definition, data defects and representativeness limitation under Uncertainty.
  5. Name the Steering Committee, Process Owner, Security Owner and Programme Lead decisions under Sign-off.
  6. Define the exact facts and calculations that Word Agent may reuse under Transfer.
  7. Score the handoff in the Evaluation workbook. Release only if the total is at least 8, Uncertainty and Sign-off both score 2, and no critical issue remains.

Exercise 6: Create the decision paper

  1. Open Word Agent from the Tools menu or All Agents. If it is absent, open the approved blank Word document and use Copilot in Word.
  2. Attach only the released TRUST handoff and named sources.
  3. Ask the agent to create the document directly. Do not manually retype the report.
  4. Open the generated Word file and compare every figure and status with the handoff.
  5. Correct only the affected statement if a figure or status is wrong.
Word Agent — controlled decision paper
Using only the approved TRUST handoff, create a two-to-three-page Project Nova Phase 2 decision paper.

Include the decision question, evidence summary, reconciled Researcher and Analyst findings, three options, conditions, evidence limitations, decisions and owners, and a source map.

Preserve citations and the Confirmed, Calculated, Proposed and Not confirmed labels. Do not invent a recommendation or record an approval that is absent.

Exercise 7: Create the steering presentation

  1. Review and human-approve the decision paper for transfer.
  2. Open PowerPoint Agent from Tools or All Agents. If unavailable, use Copilot in PowerPoint.
  3. Attach the approved decision paper and source map.
  4. Ask the agent to create a six-slide editable presentation.
  5. Verify 46 of 120, 38.3%, 74 of 120 and 61.7% against Excel.
  6. Confirm that the final slide asks humans to decide and does not claim approval.
PowerPoint Agent — steering deck
Using the approved Project Nova decision paper and source map, create a six-slide steering presentation:
1. decision question;
2. evidence and current position;
3. Researcher view;
4. Analyst view with editable chart;
5. three options and conditions;
6. decisions required and owners.

Keep all figures editable and traceable. Do not change any number, evidence status, constraint or decision owner.

Exercise 8: Optional Cowork follow-up

Cowork can act across Microsoft 365, so use it only after the action list has been approved. Microsoft documents that Cowork pauses for approval before important actions; this lab intentionally stops at that boundary.

  1. Open Cowork in Microsoft Copilot if it is available.
  2. Attach the approved action list, not the raw agent reports.
  3. Paste the prompt below.
  4. Watch the proposed steps.
  5. When Cowork presents a consequential action or approval button, stop. Do not send, post, schedule or change a system in this workshop.
  6. Record the action, evidence, owner, risk and approval boundary in the Evaluation workbook.
Cowork — prepare, then stop
Using only the approved Project Nova decisions and actions, prepare a follow-up plan with:
- action;
- owner;
- due date;
- source decision;
- approval status;
- next supported step.

Do not send messages, schedule meetings, change files or systems, create commitments, or execute consequential actions. Stop and show me the approval boundary.

Exercise 9: Final verification
