Every person, approval, request and business value in this pack is fictional. Do not replace the files with confidential customer, employee or production evidence during the workshop.

Case: one request, ten visual representations

Project Nova contains an approved access request for FinanceHub. The same core information appears in several formats of different quality. Some pages are clean. Others are blurred, rotated, cropped or visually complex.

Your task is to extract the requested fields without silently repairing, guessing or combining evidence. You must distinguish what Copilot can read from what the organisation can trust.

RiskExampleRequired behaviour
Character substitutionAR-2048 may look like AR-2O48; CC-4710 may be confused with similar digits.Compare character by character and mark uncertainty.
Missing contentThe cropped page does not show approver, status or approval controls.Return Not confirmed. Never fill from memory.
Visual interpretationCheckboxes use different marks; a stamp and signature appear in the hybrid PDF.Describe the visible mark and require human confirmation.
Authority conflictA handwritten note proposes a later end date.Keep the printed approved date until the authorised approver confirms the change.
Row associationA photographed table contains nearby requests and similar cost centres.Keep every extracted value linked to the correct Request ID row.

Learning objectives

  • test image and scanned-document analysis without assuming accuracy;
  • identify quality, crop, orientation, handwriting, checkbox and table-association risks;
  • require page or visual-region evidence for every extracted field;
  • use Not confirmed instead of guessing;
  • separate printed facts, handwritten proposals, stamps and signatures;
  • update the validation workbook directly or through a structured file import;
  • release only human-approved fields to the controlled business record;
  • prove that a one-source replacement changes only the expected results.

The IMAGE framework

IMAGE validates the extraction. TRUST then controls whether the verified value may be transferred into an official record.

GateQuestionRequired evidence
I - Image qualityIs the page clear, complete, correctly rotated and readable?Resolution, contrast, rotation, crop and page-completeness note.
M - Missing contentIs anything cropped, obscured, blurred or absent?Not confirmed status for every affected field.
A - AccuracyDoes the extracted value exactly match the visible evidence?Character-level comparison for IDs, dates, amounts and controls.
G - Ground truthCan the value be verified against an authoritative source?Named source, page or region, version and authority.
E - EscalationCan the field safely enter the business record?Named human reviewer, approval state and stop condition.
Do not confuse matching text with approval

An exact match can still be Proposed, Superseded or outside the source owner's authority. Accuracy and authority are separate controls.

Exercise 1: Establish the authoritative control

  1. Open 01_Project_Nova_Control_Text.pdf yourself.
  2. Record its filename, version and status as the authoritative printed comparison.
  3. Open the Validation Register and review the Read Me sheet.
  4. Do not open the trainer answer key during the first pass.
Blind first pass

If you want a stronger test, keep the Workshop Comparison Value column out of view until Copilot has completed the extraction.

Exercise 2: Test the clean scan

  1. Attach 02_Project_Nova_Clear_Scan.png to Copilot Chat.
  2. Attach or reference the Validation Register when your experience supports file editing.
  3. Paste the extraction prompt below.
  4. Verify the Request ID, dates, cost centre, amount and checkbox values character by character.
  5. Do not release any field yet.
Extract one source without guessing
Analyse the attached Project Nova image or scanned document. Do not infer an unreadable, cropped or ambiguous value.

Return one row per requested field with these columns:
Source file | Page/visual region | Field | Extracted value | Visual evidence | Confidence (High/Medium/Low) | Image quality issue | Evidence status | Verification required

Requested fields:
Request ID; Requester; Business unit; Access type; Environment; Effective date; End date; Cost centre; Licence cost; Approver; Status; Manager approval; Security approval; MFA required; Privileged access.

Use Not confirmed when a value is missing, cropped, blurred, handwritten, ambiguous or only inferred. Preserve leading zeros, punctuation, currency, decimals and date format exactly. Explain how each checkbox selection was visually indicated. Separate printed facts from handwriting, stamps and signatures. Do not treat a stamp or signature as proof of identity or approval scope.

Exercise 3: Stress-test image quality

  1. Run the same prompt against the low-resolution scan, rotated phone photo and cropped page.
  2. Do not rotate, enhance or explain the files before the first extraction.
  3. Record every omission, substitution, unsupported inference and confidence change.
  4. If Copilot returns a plausible value that is not visible, classify it as Unsupported, not Correct.
The cropped-page test

Approver, status and approval controls are absent. The correct result is Not confirmed even though those values exist in another file.

Exercise 4: Test visual meaning and authority

  1. Test the checkbox form. Require Copilot to explain the visual mark used for every selection.
  2. Test the handwritten-correction image. Keep the printed end date separate from the handwritten proposal.
  3. Test the photographed table. Require every value to stay within the AR-2048 row.
  4. Test the hybrid PDF. Do not let a stamp or signature become automatic proof of the signer or approval scope.
Challenge the apparent approval
Separate the printed facts, checkbox selections, handwritten content, stamp and signature in this source.

For each element, state:
1. what is visibly present;
2. what text or state you extracted;
3. whether the element is readable;
4. whether it proves authority or approval;
5. the evidence status;
6. the human verification still required.

Do not identify a signer from handwriting or assume that a stamp approves every field.

Exercise 5: Write results without manual copying

Path A - Direct workbook update

  1. Attach the source and Validation Register to the file-editing Copilot experience.
  2. Ask Copilot to update only columns E-G and J in Extraction Review.
  3. Open the edited workbook and inspect the exact cells Copilot changed.
Direct workbook update
Write this extraction directly into the matching source and field rows of Lab_11_Image_Extraction_Validation_Register.xlsx.

Update only:
- AI Extracted Value;
- Confidence;
- Image Quality Issue;
- Evidence Status.

Do not change Workshop Comparison Value, Match Status formulas, IMAGE Decision, Reviewer, Review Notes, Release Eligible, Verified Business Record or Audit Log.

Path B - Structured file import

Create a structured import file
Create a downloadable CSV or XLSX named Lab_11_AI_Extraction_Result using exactly these headers:
Source File, Page or Region, Field, Extracted Value, Visual Evidence, Confidence, Image Quality Issue, Evidence Status, Verification Required.

Do not place narrative before or after the table. Do not guess missing values.
  1. Download the generated file.
  2. In Excel, open the Validation Register.
  3. Select Data > From Text/CSV.
  4. Select the generated file, verify the headers and choose Load To.
  5. Load to a new sheet and use Copilot in Excel to merge matching source-field rows into the permitted columns.

Exercise 6: Verify and release approved fields

  1. Apply every IMAGE gate to each material extraction.
  2. Set IMAGE Decision to Human approved, Hold or Reject.
  3. Filter Release Eligible to Yes.
  4. Ask Copilot in Excel to update only matching fields in Verified Business Record.
  5. Require one Audit Log row per changed field.
  6. Confirm that the handwritten end date remains Proposed and is not released.
Release only approved fields
Using only Extraction Review rows where Release Eligible = Yes, update the matching field in Verified Business Record.

Change only Approved Value, Evidence Status, Source File, Human Reviewer and Approval Date for the named field. Preserve every unrelated value and formula.

Append one Audit Log row with field, previous value, new value, source file, source region, IMAGE decision and approver. Do not release any Not confirmed, Proposed, Unsupported, Conflict, Hold or Reject value.

Exercise 7: Run the one-input-change test

  1. Keep the original S03 extraction and review history.
  2. Replace only the low-resolution source with 10_Project_Nova_Improved_Replacement.png.
  3. Run the same extraction prompt without changing another parameter.
  4. Compare S03 and S10. Request ID, cost centre, amount and date confidence may improve.
  5. Confirm that results from every other source and every prior approval remain unchanged.
Controlled replacement comparison
Compare only the prior low-resolution extraction with 10_Project_Nova_Improved_Replacement.png.

Report only changed extracted values, confidence or quality issues. Preserve the original S03 result and audit history. Do not modify any result, decision or approval linked to another source.

Optional enterprise path: SharePoint OCR

When an administrator has enabled SharePoint OCR, upload a copy of the evidence to the approved test site and compare the extracted text with the one-off Copilot result.

  1. Confirm with the site administrator that OCR is enabled for the intended SharePoint site.
  2. Upload a new copy after enablement. Existing files are not retroactively processed automatically.
  3. For supported image files, inspect the extracted-text metadata when available.
  4. For PDF or TIFF evidence, test search indexing and record that extracted text may not appear in the same metadata column.
  5. Apply IMAGE before any OCR result enters a controlled record.
OCR is a service capability, not an approval workflow

It can improve search and text extraction, but it does not decide source authority, business meaning or whether a handwritten change is approved.
