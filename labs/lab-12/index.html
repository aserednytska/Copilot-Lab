Microsoft 365 Copilot - Lab 12

Turn a Copilot Response into a Controlled Collaborative Page

Transform a private Copilot response into persistent, editable and shareable working content - without treating collaboration as approval or losing the authority of the original sources.

Level 200Duration 55-70 minFormat Ground, promote, collaborate, release
Core question: When can a useful Copilot response safely become shared team content and then a formal business deliverable?

Lab details

Project Nova weekly reviewCopilot Chat, Copilot Pages, Loop-based collaboration and Copilot in ExcelTRUST before sharing and transferA source-grounded working Page, controlled edit history and approved formal output
A Page is durable, not automatically authoritative

Copilot Pages makes an AI response persistent, editable and shareable. It does not make the response correct, approved or suitable as an official business record.

Case: a useful response trapped in one person's chat

Project Nova has completed a weekly review. The project manager wants Copilot to combine the approved status, risks, decision record, meeting transcript and post-meeting Teams corrections into one weekly update.

The first Copilot response may be useful, but the team cannot safely collaborate on a private chat response. The team needs a persistent Page that can be refined together, while keeping approved decisions separate from meeting discussion and manager preferences.

Source signalWhat it saysCorrect treatment
Decision D-031Maximum 40 users; conditions required before UATApproved and authoritative
Status Report v415 September is a planning targetConfirmed target label, not an approved date
Transcript“Fifteen September sounds workable”Discussion, not approval
Manager commentPreference for 60 usersProposed only
Post-meeting chatSarah corrects the dashboard owner and confirms responsibilityClaim-level operational correction requiring review

Learning objectives

  • choose Copilot Pages when a useful response needs to become persistent and collaborative;
  • distinguish Chat, Pages, Loop, Notebooks and formal records;
  • ground the draft in ranked sources before promoting it;
  • create a Page directly rather than manually copying the response;
  • share only the Page or synchronized component, not the private chat;
  • control collaborative edits and recover an earlier version;
  • update only claims affected by a replacement source;
  • convert the released Page directly to Word or PDF;
  • keep formal approval and the system of record under human control.

Availability varies

Pages, Copilot features, sharing controls and conversion options can differ by account, tenant policy and Microsoft rollout. Missing functionality is a capability finding, not a reason to copy content into an uncontrolled tool.

Exercise 1: Establish the authority hierarchy

  1. Download and open the six Project Nova source documents.
  2. Open the Source Register workbook and review each source's authority and permitted use.
  3. Confirm that D-031 controls UAT scope and entry conditions.
  4. Confirm that Status Report v4 provides approved figures but labels 15 September as a planning target.
  5. Confirm that the transcript is discussion evidence and the Teams chat contains mixed-authority claim-level corrections.

Exercise 2: Generate the grounded weekly update

  1. Open Microsoft Copilot with your organizational account.
  2. Open Copilot Chat and attach the approved decision, status and risk files, then the transcript and Teams chat.
  3. Paste the grounded weekly update prompt below.
  4. Inspect every number, owner, date, decision and scope before continuing.
  5. If Copilot shows 15 September or 60 users as approved, correct the response in Chat. Do not promote an incorrect draft.
Ground the weekly update
Using only the attached Project Nova sources, prepare a weekly decision update with these sections:
- Confirmed facts;
- Approved decisions;
- Actions with owner, due date and source;
- Risks;
- Proposed changes;
- Open questions;
- Source map.

Rank the approved Decision Record above status and risk records, named-owner chat corrections, transcript discussion and manager preferences.

Preserve 40 users as the approved maximum. Treat 2026-09-15 and 60 users as Proposed unless an approved source says otherwise. Do not infer approval from phrases such as “sounds workable.”

Exercise 3: Create the Copilot Page directly

  1. Below the verified Copilot response, select the pencil-shaped Edit in Pages button.
  2. The Page opens beside Copilot Chat. Select the title and rename it Project Nova Weekly Decision Page.
  3. If your experience supports automatic Page creation, you may instead ask Copilot to “Create a Page called Project Nova Weekly Decision Page.”
  4. Ask Copilot to keep Confirmed, Calculated, Proposed and Not confirmed visibly separated.
  5. Compare the Page with the Example Finished Copilot Page and the Claim Review sheet.
No manual copy

The pencil button turns the response into a Page. Do not manually copy the generated response into Loop, Word or another app.

Exercise 4: Share the Page without sharing the private chat

  1. In the upper-right corner of the Page, select Share.
  2. Choose Page link to share this single Page. Recipients can collaborate on the Page without access to your original Copilot chat.
  3. Alternatively, choose Copy component to place a synchronized component in Teams, Outlook, OneNote or another supported Microsoft 365 app.
  4. Review link permissions before sending. Use only workshop participants who should access the synthetic case.
  5. Ask a partner to make only the authorized dashboard-owner correction.
Controlled owner correction
Update only the dashboard and communication action owner from Tomas Weber to Sarah Kim, due 2026-09-10, based on the named-owner correction in the post-meeting Teams chat.

Record the previous value, new value, source and verification status. Do not change the timeout-test owner, UAT scope, start-date status or any approved decision.

Exercise 5: Review and recover a Page version

  1. Ask the collaborator to test an unauthorized change from 40 to 60 users.
  2. Confirm that the change conflicts with D-031 and must not be released.
  3. In the upper-right corner of the Page, use the left arrow to browse earlier versions.
  4. Select Restore version if the unauthorized scope is present, or cancel if the current version is already correct.
  5. Record the change and review decision in the Collaboration Changes sheet.
Version history is not approval history

Restoring an earlier version can recover content. It does not prove that the recovered content was approved by the correct business owner.

Exercise 6: Update Excel directly

  1. Open the Copilot Page Source and Change Register in Excel.
  2. Use Copilot in Excel with the source files and Page available.
  3. Ask Copilot to populate or update only the Claim Review and Collaboration Changes fields that it can support with evidence.
  4. Do not ask Copilot to fill Human reviewer, Review decision, Release owner or Release decision. Those are human controls.
  5. If direct workbook editing is unavailable, ask Copilot to create a structured downloadable CSV/XLSX matching the exact headers, then import it through Data > From Text/CSV. Do not manually copy rows.
Write findings directly into the workbook
Using the verified Project Nova Page and named source documents, update the matching rows in the Claim Review and Collaboration Changes sheets directly.

Update only Claim, Page value, Source ID, Source location, Authority, Evidence label, Previous value, New value, Change source and Expected impact.

Do not edit Human reviewer, Review decision, Release owner, Release date or Release decision. Do not add unsupported claims.

Exercise 7: Run the one-change test

  1. Replace Status Report v4 with approved Status Report v5.
  2. Ask Copilot to compare the Page claim by claim and update only the directly affected value.
  3. Expected change: High-severity defects decreases from 2 to 1.
  4. Total defects, status, budget, security checks, risks, owners, dates, 40-user scope and D-031 must remain unchanged.
  5. Record expected and observed impact in the workbook.
Controlled source replacement
Replace Status Report v4 with approved Status Report v5. Compare the Page claim by claim.

Update only values directly changed by the approved replacement source. List every Page element changed and every protected element left unchanged. Preserve all other sources and the collaboration history.

Exercise 8: Release the Page to Word or PDF

  1. Complete the TRUST checklist and the Release Check sheet.
  2. Obtain the named human approval and confirm the sharing scope.
  3. In the upper-right corner of the Page, select Create.
  4. Select Document. Copilot prepares a draft; select Open Word to open it in Word for the web.
  5. Or select PDF to create a fixed Page snapshot.
  6. Compare the generated output with the released Page and store the approved version in the organization's official records location.
Current product limitation

Microsoft currently documents Page conversion to Word and PDF. The previously available conversion from a Copilot Page to PowerPoint is currently unavailable.

Find the Page later

  1. Sign in to microsoft365.com.
  2. Select Library in the left navigation.
  3. Pages appear under Pages.
  4. Open All sources and select Created by you when you need to narrow the list.
