Microsoft 365 Copilot · Lab 3

From Copilot Chats to a SharePoint Knowledge Backlog

Review separate Copilot conversations, preserve their authority and promote only verified, reusable knowledge into a controlled shared record.

Level 200 Duration 40–50 min + 10–15 min optional Format Guided hands-on lab
Workshop path: Copilot Chat, shared knowledge and governance

Lab details

LevelPersonaDurationPurpose
200Consultant, business analyst, project manager, PMO40–50 minutes, plus 10–15 minutes for the optional Notebook pathTurn useful personal chat work into a verified, permission-controlled SharePoint knowledge backlog.

Download the participant files

Download all four files before starting. The seed pack creates the chat history; the Word backlog becomes the shared record.

  • Project Atlas Chat History Seed Pack (.docx) — five separate synthetic conversations.
  • Copilot Conversation Knowledge Backlog (.docx) — the controlled Word template to upload to SharePoint.
  • Copilot Prompt Card (.pdf) — extraction, verification and query prompts.
  • Backlog Governance Quick Guide (.pdf) — the CLEAR model, promotion gate and lifecycle rules.
Synthetic data

The case contains no customer, employee or production information. Use only the supplied files during the workshop.

The central control rule

Promote verified knowledge, not raw transcripts

Chat history is a personal working surface. The SharePoint backlog is a reviewed shared record. Copy only concise, reusable information that has passed a human evidence check.

Information surfaceBest useDo not assume
Copilot chat historyReturn to a prior working conversation and continue it.That every useful chat is a governed or durable project record.
SharePoint Word backlogStore concise, verified project knowledge with authority, status and evidence.That it replaces the formal approval or requirements system.
Copilot NotebookCurate selected sources in an AI workspace for synthesis.That its synthesis is automatically the agreed organisational position.
Formal system of recordHold approved requirements, decisions, controls and official records.That a chat or backlog entry can bypass its governance.

Learning objectives

After completing this lab, you will be able to:

  • organise separate Copilot chats so they can be reviewed later;
  • distinguish assumptions, proposals, confirmed decisions, actions and unrelated conversations;
  • extract one evidence-grounded backlog candidate from one conversation;
  • apply a human promotion gate before adding shared knowledge;
  • preserve superseded records to show decision evolution;
  • move selected Copilot chats into a curated Copilot Notebook;
  • compare Notebook synthesis with the controlled SharePoint backlog;
  • query the SharePoint Word backlog by Backlog ID and status.

Running scenario

Project Atlas is preparing for user acceptance testing. Five Copilot conversations were created at different moments. They contain an early assumption, a revised proposal, a confirmed steering decision, useful but unapproved training ideas and an unrelated project with a similar name.

Your task is to create a backlog that preserves the history without allowing a draft, a newer-looking proposal or a false project-name match to become the current approved position.

Expected challenge

The most recent or most polished conversation is not necessarily authoritative. The valid current answer must be both Current and Confirmed.

Prerequisites

  • A work or school account with access to Microsoft Copilot Chat.
  • Permission to upload a Word document to the workshop SharePoint library.
  • Permission to open and edit that Word document.
  • The four participant downloads above.
  • For the optional Notebook path: access to Copilot Notebooks and a SharePoint or OneDrive service plan.
  • Approximately 50 minutes, plus 10–15 minutes if you complete the optional Notebook path.
Capability check

Referencing a Word file in Copilot Chat is not the same as editing it. If direct document editing is unavailable, prepare the candidate in Copilot, verify it and paste the approved content into Word manually.

Exercise 1: Create five separate history items

  1. Open the Chat History Seed Pack.
  2. Start a new Copilot conversation for Seed 1 and paste the complete seed prompt.
  3. Repeat in a new conversation for Seeds 2–5.
  4. Do not combine the seeds or correct their differences yet.
  5. Confirm that five separate items appear in your Chats list.
Why separate chats?

The exercise demonstrates that useful project knowledge can be scattered across conversations and that similar titles do not prove the same project or authority.

Exercise 2: Review and classify the chat history

Open each conversation and note its project, date, purpose, information type and evidence authority. Do not ask Copilot to merge all five conversations into one answer.

Review questionPossible value
Which exact project is this about?Project Atlas or another named project
What kind of information is present?Assumption, proposal, decision, action, prompt or insight
What is its authority?Draft, Recommended or Confirmed
What should happen to it?Current, Superseded, Hold or Rejected

Exercise 3: Extract one backlog candidate

Run this prompt inside one conversation at a time. Keep the original conversation open so you can compare every field.

Single-conversation extraction
Review only this Copilot conversation.

Prepare one candidate record for the Copilot Conversation Knowledge Backlog.

Return:
- Project
- Chat title
- Conversation date
- Purpose
- Information type: Assumption, Proposal, Decision, Action, Prompt or Insight
- Extracted outcome
- Owner
- Deadline
- Authority: Draft, Recommended or Confirmed
- Status
- Supersedes another record: Yes or No
- Keywords
- Exact evidence from this conversation
- Missing or conflicting information

Do not use information from another conversation. Write Not confirmed when a value is missing. Do not create a decision or action from a suggestion.

Exercise 4: Apply the human verification gate

Compare the candidate with the exact conversation before it can enter SharePoint.

Backlog exception review
Compare the proposed backlog record with this original conversation.

Flag:
1. Any project-name mismatch
2. Any summary not supported by the conversation
3. Any proposal labelled as a confirmed decision
4. Any inferred owner or deadline
5. Any missing conflict
6. Any record that should be Rejected, Hold or Superseded

Do not rewrite the record. Return only exceptions and a clarification question for each.
  • Approve only when project, date, type, authority, status and evidence are correct.
  • Hold when required evidence is missing or conflicting.
  • Reject the wrong project or unsupported, non-reusable information.
  • Supersede an earlier position when a later confirmed record explicitly replaces it.

Exercise 5: Build the SharePoint Word backlog

  1. Upload Copilot Conversation Knowledge Backlog.docx to the workshop SharePoint library.
  2. Confirm that the intended participants can open it.
  3. Use one detailed record for each reviewed conversation.
  4. Complete the index only after the detailed record has passed verification.
  5. Add the verifier’s name and review date.
  6. Do not paste the complete chat transcript.
Preserve decision evolution

Do not delete the 8 September assumption or 9 September proposal. Mark them Superseded when the confirmed 10 September decision becomes Current.

Exercise 6: Resolve current, superseded and rejected records

Review the five candidate records as one controlled set. The record with the newest conversation date does not automatically win.

Decision evolution
Using only the referenced backlog document, create a Project Atlas decision timeline.

For every record include:
- Backlog ID
- Conversation date
- Information type
- Authority
- Status
- Extracted outcome
- What it supersedes

Preserve assumptions and proposals as history. Clearly identify the one current confirmed position. Flag any sequence that cannot be proven from the document.

Exercise 7: Query the controlled backlog

  1. Open a new Copilot Chat.
  2. Type / and select the exact SharePoint file Copilot Conversation Knowledge Backlog.docx.
  3. Run the current-position prompt.
  4. Check that every answer cites a Backlog ID.
Current project position
Using only the referenced Copilot Conversation Knowledge Backlog document:

1. What is the current confirmed UAT start date?
2. Which previous dates were superseded?
3. Who owns migrated-user sample validation?
4. Which access restriction remains active?
5. Which Project Atlas questions remain unresolved?
6. Which records were rejected or excluded?

For every answer, cite the Backlog ID.
Treat only records with Status Current and Authority Confirmed as final.
Do not use Superseded, Rejected or unrelated records as the current position.

Exercise 8 (optional): Move selected chats to a Copilot Notebook

Use this path when you want an ongoing AI workspace that combines several related chats and project files. In this case, create one curated Project Atlas notebook, include only the four relevant Project Atlas conversations and deliberately exclude the unrelated finance-tool conversation.

Part A: Create the destination notebook

  1. Go to Microsoft Copilot and sign in with your work or school account.
  2. In the left navigation, select Notebooks, then All notebooks.
  3. Select New notebook.
  4. Name it Project Atlas – Working History.
  5. Under Add content to References, search for and select Copilot Conversation Knowledge Backlog.docx.
  6. Select Create.
If Notebooks is not visible

Open the Microsoft 365 app launcher (the waffle menu) and select Notebooks. If it is still unavailable, your licence, SharePoint or OneDrive service plan, rollout stage or organisation policy may not support it. Continue with the SharePoint backlog path in Exercise 7.

Part B: Move each selected chat

  1. Return to Copilot Chat.
  2. In the left-side Chats list, locate the first Project Atlas conversation.
  3. Next to the chat title, select More (…).
  4. Select Move to notebook.
  5. Choose Project Atlas – Working History as the destination notebook.
  6. Repeat the same steps for Seeds 2, 3 and 4.
  7. Do not move Seed 5. It belongs to another project despite the similar name.
  8. Open Notebooks → Project Atlas – Working History and confirm that the four selected chats and the SharePoint backlog appear as notebook references.
What “Move to notebook” means

The command adds the conversation to the selected Copilot Notebook as working context. It does not make every statement in that chat approved, and it does not replace the controlled SharePoint backlog or the formal system of record.

Part C: Give the notebook a control instruction

  1. Open the notebook.
  2. In the upper-right corner, select More options (…), then Instructions.
  3. Paste the instruction below and select Save.
Notebook control instruction
Treat Copilot Conversation Knowledge Backlog.docx as the authoritative project record.

Use moved Copilot chats only as supporting working history.

For every answer:
- separate Assumptions, Proposals, Confirmed decisions, Actions and Unresolved questions;
- treat only backlog records with Status Current and Authority Confirmed as final;
- cite the Backlog ID for every current conclusion;
- preserve conflicts and superseded positions;
- never infer an owner, deadline or approval;
- flag any source that appears to concern another project.

Part D: Work inside the notebook

Notebook synthesis test
Using only the references in this notebook, explain how the Project Atlas UAT position evolved.

Create four sections:
1. Working assumptions and proposals from the moved chats
2. Current confirmed position from the SharePoint backlog
3. Superseded or conflicting information
4. Unresolved questions

For every current conclusion, cite the Backlog ID.
Do not treat the moved chats as approval evidence.

Check that the notebook uses Seeds 1–4 as history, excludes Seed 5 and still treats the SharePoint backlog as authoritative.

Exercise 9: Compare chat, Notebook and controlled knowledge

  1. Ask a general Copilot chat, without referencing the backlog, for the current Project Atlas UAT date.
  2. If you completed Exercise 8, ask the same question inside Project Atlas – Working History.
  3. Compare both answers with the file-grounded answer from Exercise 7.
  4. Identify which answer is traceable to authority, status and Backlog ID.
ApproachWhat it is good forControl question

Teaching point

The Notebook is the optional working environment; the SharePoint backlog is the controlled shared record. Moving a chat makes it available for synthesis, not automatically correct or approved.

The CLEAR operating model

StepMeaningEvidence required
C — ClassifyRecognise temporary, working or evidence-bearing chat.Purpose and project are known.
L — LabelRename useful conversations consistently.Project, topic, status and date.
E — EvaluateSeparate assumptions, proposals and decisions.Exact supporting conversation text.
A — Archive deliberatelyPromote only reusable verified information.Human approval and Backlog ID.
R — Review or retireKeep current, supersede, close or reject.Status, authority and review date.

Word document or SharePoint List?

Word in SharePointSharePoint List
Best for a small or medium reviewed knowledge backlog.Best for hundreds of records and multiple contributors.
Supports narrative context and source evidence.Supports filtering, views and structured status reporting.
Simple to demonstrate and reference as one file.Better for Power Automate and Power BI integration.
Requires discipline to keep the index current.Requires list design, columns and governance setup.
Workshop recommendation

Use Word for this lab. Move to a SharePoint List when scale, concurrent updates, dashboards or automation become primary requirements.

Success criteria

Limitations and good practice

Risk or limitationControl
Chat-history interfaces are designed for reopening conversations, not for governed project reporting.Promote verified reusable information into the shared backlog.
Copilot may favour recent or polished wording over authority.Require Authority, Status and Backlog ID in every answer.
Similar project names can produce a false match.Verify the exact project identity and reject unrelated records.
Referencing a file does not guarantee direct editing.Separate extraction, human approval and the Word update.
Copilot can use only content the signed-in user is permitted to access.Review SharePoint permissions before the lab.
Deleting a visible chat and compliance deletion are different processes.Apply organisational retention, sensitivity and records-management rules.
Chat-history personalisation or inferred memory is selective and dynamic.Do not use memory as the formal project record; reference the controlled file.
Moving a chat to a Notebook does not verify or approve its content.Keep the SharePoint backlog authoritative and apply the same human promotion gate.
Notebook features may be rolling out gradually or restricted by licence and policy.Use the direct SharePoint file-reference path if Notebooks or Move to notebook is unavailable.
Sharing a Notebook can also affect access to linked files, while each user’s Notebook chat remains private.Review every reference and its permissions before sharing the Notebook.

Test your understanding

  1. Why is the 10 September decision authoritative even if another chat is opened more recently?
  2. What value does a Superseded record provide?
  3. When should a useful idea remain Hold instead of becoming an action?
  4. Why is human verification necessary before SharePoint promotion?
  5. What belongs in the formal system of record rather than this knowledge backlog?
  6. When would you replace the Word backlog with a SharePoint List?
  7. When is moving selected chats to a Notebook useful, and why does that not make the Notebook the formal project record?
Lab complete

You have converted scattered working conversations into a traceable knowledge record without losing authority, conflicts or decision history.
